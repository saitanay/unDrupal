# Skill 34 — Export Acquia Site Studio (Cohesion)

Extract all visual page builder data from an Acquia Site Studio (formerly Cohesion) installation. Components, templates, styles, layout canvas JSON, and style guide tokens. Produce portable definitions that a target platform can consume without the Site Studio rendering API.

---

## Why Site Studio Complicates Migration

Site Studio stores page layouts as opaque JSON blobs inside `cohesion_layout` entities. It generates CSS and Twig templates server-side through an external API call. Nothing renders without that API connection.

A standard Drupal config export grabs the YAML shells of components and templates but misses file dependencies, skips rebuild metadata, and breaks data integrity checks on import. Site Studio's own packaging system exists for a reason — it handles file entity references, validation, and rebuild ordering that Drupal's core config sync does not.

The layout canvas JSON contains the full component tree for every node, block, and template. Nested elements, property values, responsive overrides, animation settings, column configurations — all encoded in a single `json_values` string field. Parsing this blob is the core challenge.

Sites running Site Studio often run on Acquia Cloud or Acquia Site Factory. Cross-reference skill 36 for Site Factory multi-site extraction patterns.

## Architecture Overview

Site Studio has four layers. Each stores data differently.

### 1. Config entities (site-building layer)

Templates, components, styles, helpers, and website settings. Stored as Drupal config entities in YAML. Each entity contains a `json_values` property holding the layout canvas JSON for that definition.

### 2. Layout canvas field (content layer)

A `cohesion_layout` field type added to content entities (nodes, block_content, custom entities). The field creates a reference to a `cohesion_layout` entity that stores the per-entity JSON blob in its `json_values` base field.

### 3. Generated assets (rendering layer)

Twig templates and CSS stylesheets generated by the Site Studio API. Stored on disk in `sites/default/files/cohesion/`. These are build artifacts — they get regenerated on rebuild.

### 4. Style guide tokens (theming layer)

Key-value pairs surfaced through Drupal's theme settings page. Each token replaces a static value in styles or templates. Stored as `cohesion_style_guide` config entities.

## Config Entity Types

### Components

Machine name prefix: `cohesion_component.*`

Components are reusable building blocks. Each has:
- A **layout canvas** defining the rendered HTML structure (elements, containers, columns)
- A **component form** defining the editor-facing fields (inputs, WYSIWYGs, selects, image uploaders, entity references, toggles, color pickers)
- **Drop zones** where editors can nest child components
- A **category** for grouping in the sidebar browser
- **Placement restrictions** controlling where the component can be used

```bash
# List all component configs
ls config/sync/cohesion_component.cohesion_component.* 2>/dev/null
```

Each component form field has:
- A UUID used as the key in the model JSON
- A `uid` property identifying the form element type
- A `machine_name` (optional, used for JSON:API output)
- A `translate` flag for multilingual extraction
- A `schema` with a `type` property (`object`, `string`, `boolean`, etc.)

### Helpers (Layout helpers)

Machine name prefix: `cohesion_helper.*`

Pre-built layout snippets. Like components but without a form — they insert a fixed structure. Helpers can be categorized and restricted to specific drop zones.

### Style helpers

Machine name prefix: `cohesion_style_helper.*`

Reusable bundles of CSS properties that can be applied to elements. Not the same as custom styles — style helpers attach through a different mechanism in the layout canvas.

### Custom styles

Machine name prefix: `cohesion_custom_style.*`

Each generates a CSS class (e.g., `.coh-style-max-width---narrow`). Built using the style builder UI. Can extend other custom styles. Properties:
- `class_name`: generated CSS class
- `json_values`: style properties and responsive overrides
- `custom_style_type`: base element type this style targets
- `parent`: parent custom style if extending

### Base styles

Machine name prefix: `cohesion_base_style.*`

Default CSS applied to HTML elements (`h1`, `p`, `a`, `ul`, etc.) and pseudo-elements. No class names generated — these style bare elements.

### Master templates

Machine name prefix: `cohesion_master_templates.*`

Page-level layout wrappers. Define the shell around content: header, footer, sidebar regions, menu placement. Each master template targets specific content types or pages through selection logic.

The layout canvas for a master template contains Drupal region elements, menu elements, and structural layout (rows, columns, containers).

### Content templates

Machine name prefix: `cohesion_content_templates.*`

Per-bundle, per-view-mode templates. Replace Drupal's default entity rendering. A content template for `article` in `full` view mode controls how article nodes render.

Content templates connect to Drupal fields through tokens (e.g., `[node:title]`, `[node:field_image]`). The token browser inside Site Studio maps to standard Drupal token patterns.

### View templates

Machine name prefix: `cohesion_view_templates.*`

Replace the row/field output of Drupal Views. Contain special elements: view item, pattern repeater, filter, pagination, view variable.

### Menu templates

Machine name prefix: `cohesion_menu_templates.*`

Control menu rendering. Contain menu list container, menu list item, menu link, and menu button elements. Support multi-level menus with interactivity states.

### Website settings

Config prefixes:
- `cohesion_website_settings.cohesion_color.*` — Color palette
- `cohesion_website_settings.cohesion_font_stack.*` — Font stacks
- `cohesion_website_settings.cohesion_icon_library.*` — Icon font libraries
- `cohesion_website_settings.cohesion_responsive_grid_settings.*` — Breakpoints and grid
- `cohesion_website_settings.cohesion_scss_variable.*` — SCSS variables
- `cohesion_website_settings.cohesion_base_unit_settings.*` — Base unit (px/rem)

### Style guides

Machine name prefix: `cohesion_style_guide.*`

Form definitions that expose design tokens through Drupal theme settings. Each field generates a token like `[style-guide:heading-1-font-color]`. Supported field types: input, select, toggle, image uploader, color picker, icon picker, range slider, font picker.

## Layout Canvas JSON Structure

The layout canvas is a JSON object stored in the `json_values` column. Every config entity and every `cohesion_layout` content entity uses this format.

### Top-level keys

```json
{
  "canvas": [],
  "mapper": {},
  "model": {},
  "previewModel": {},
  "variableFields": {},
  "meta": {}
}
```

| Key | Purpose |
|-----|---------|
| `canvas` | Ordered tree of elements. Defines nesting and order. |
| `mapper` | Maps element UUIDs to their model entries. Rarely needed for extraction. |
| `model` | Keyed by element UUID. Holds all property values, styles, and component field data. |
| `previewModel` | Preview-time overrides. Ignore during migration. |
| `variableFields` | Tracks which fields use tokens/variables instead of static values. |
| `meta` | Metadata including `fieldHistory`. |

### Canvas array

Each entry in `canvas` represents an element:

```json
{
  "uid": "cpt_hero_banner",
  "type": "component",
  "title": "Hero Banner",
  "enabled": true,
  "category": "category-3",
  "componentId": "cpt_hero_banner",
  "componentType": "container",
  "uuid": "ac9583af-74f9-419d-9f8a-68f6ca0ef5e8",
  "parentUid": "root",
  "isContainer": 0,
  "children": []
}
```

**Element types** (the `type` field):

| Type | Meaning |
|------|---------|
| `component` | Instance of a Site Studio component. `componentId` references the component config entity. |
| `container` | Generic div wrapper. |
| `row_for_columns` | Flex/grid row. Children are `column` elements. |
| `column` | Grid column inside a row. Width set per breakpoint. |
| `wysiwyg` | Rich text block. |
| `heading` | Heading element (h1–h6). |
| `paragraph` | Paragraph element. |
| `link` | Anchor element. |
| `image` | Image element. |
| `video` | Video element. |
| `button` | Button element. |
| `slider_container` | Carousel wrapper. Children are `slide` elements. |
| `accordion_tabs_container` | Accordion/tabs wrapper. |
| `modal` | Modal dialog. |
| `drupal_block` | Embeds a Drupal block. |
| `drupal_region` | Embeds a Drupal region (master templates). |
| `drupal_menu` | Embeds a Drupal menu. |
| `drupal_field` | Renders a Drupal field (content templates). |
| `drupal_field_item` | Renders a single field delta. |
| `drupal_entity_reference` | Renders a referenced entity. |
| `drupal_breadcrumb` | Breadcrumb element. |
| `drupal_view` | Embeds a Drupal View. |
| `read_more` | Collapsible read-more wrapper. |
| `iframe` | iFrame element. |
| `inline_element` | Generic inline span. |
| `list_container` | ul/ol wrapper. |
| `list_item` | li element. |
| `blockquote` | Block quote. |
| `picture` | Picture element with source sets. |

### Model object

The model maps element UUIDs to their data. For a component instance, the model entry contains:
- `settings.title` — display title in the layout canvas
- One key per component form field (keyed by the field's UUID from the component definition)

```json
{
  "ac9583af-74f9-419d-9f8a-68f6ca0ef5e8": {
    "settings": {
      "title": "Hero Banner: Welcome"
    },
    "6b671446-cb09-46cb-b84a-7366da00be36": {
      "text": "<h1>Welcome to our site</h1>",
      "textFormat": "cohesion"
    },
    "fdaea1d1-6b7c-4aad-978a-e6981fb5eb7d": {
      "name": "White",
      "uid": "white",
      "value": {
        "hex": "#ffffff",
        "rgba": "rgba(255, 255, 255, 1)"
      },
      "class": ".coh-color-white",
      "variable": "$coh-color-white"
    },
    "e6f07bf5-1bfa-4fef-8baa-62abb3016788": "coh-style-max-width---narrow"
  }
}
```

**Model value types by form field:**

| Form element | Model value structure |
|-------------|---------------------|
| Input (text) | Plain string |
| WYSIWYG | `{ "text": "<p>...</p>", "textFormat": "cohesion" }` |
| Select | String (selected option value) |
| Toggle | Boolean |
| Link to page | `{ "url": "/path", "target": "_blank", "type": "internal" }` |
| Image uploader | `{ "path": "public://images/hero.jpg", "alt": "...", "title": "..." }` |
| Color picker | `{ "name": "White", "uid": "white", "value": { "hex": "#fff", "rgba": "..." }, "class": "...", "variable": "..." }` |
| Icon picker | `{ "value": "icon-class-name" }` |
| Entity reference | `{ "entity_type": "node", "entity": "123" }` |
| Range slider | Numeric value |
| Hidden input | String |
| Custom style class | String (the class name, e.g. `"coh-style-padding-bottom---large"`) |

### Responsive overrides

Style properties can vary by breakpoint. Site Studio uses breakpoint keys:

| Key | Breakpoint |
|-----|-----------|
| `xl` | Extra large (desktop, default) |
| `lg` | Large |
| `md` | Medium |
| `sm` | Small |
| `xs` | Extra small (mobile) |
| `ps` | Portrait small |

Properties in the model can contain per-breakpoint values:

```json
{
  "styles": {
    "xl": { "font-size": "48px", "margin-bottom": "24px" },
    "sm": { "font-size": "32px", "margin-bottom": "16px" },
    "xs": { "font-size": "24px", "margin-bottom": "12px" }
  }
}
```

### Animation and interaction

Elements can have interaction settings in their model:

```json
{
  "animateonview": {
    "animation": "fadeInUp",
    "duration": "1s",
    "delay": "0s"
  },
  "interactionModifiers": [
    {
      "interaction": "click",
      "target": ".coh-some-class",
      "action": "toggleClass",
      "value": "is-active"
    }
  ]
}
```

## Per-Entity Layout Storage

When a content type has a layout canvas field, each node gets its own `cohesion_layout` entity.

### Database tables

| Table | Contents |
|-------|----------|
| `cohesion_layout` | Base table. Columns: `id`, `revision_id`, `parent_type`, `parent_id`, `parent_field_name`. |
| `cohesion_layout_revision` | Revision table. One row per revision. Can grow large on heavily edited nodes. |
| `cohesion_layout__json_values` | (or the json_values is a base field stored in `cohesion_layout` directly) Holds the JSON blob. |
| `node__field_layout_canvas` | Entity reference field table linking nodes to their `cohesion_layout` entity. Columns include `field_layout_canvas_target_id` and `field_layout_canvas_target_revision_id`. |
| `node_revision__field_layout_canvas` | Revision table for the entity reference field. |

### Extracting layout data per node

```sql
-- Get layout canvas JSON for all published nodes
SELECT
  n.nid,
  n.title,
  cl.id AS cohesion_layout_id,
  cl.json_values
FROM node_field_data n
JOIN node__field_layout_canvas flc
  ON flc.entity_id = n.nid
  AND flc.deleted = 0
JOIN cohesion_layout cl
  ON cl.id = flc.field_layout_canvas_target_id
WHERE n.status = 1;
```

### Programmatic access

```php
$node = \Drupal::entityTypeManager()->getStorage('node')->load($nid);
$layout_canvas_field = $node->get('field_layout_canvas');
$target_id = $layout_canvas_field->getValue()[0]['target_id'];

$layout_entity = \Drupal::entityTypeManager()
  ->getStorage('cohesion_layout')
  ->load($target_id);

$json = $layout_entity->getJsonValue();  // raw JSON string
$canvas = $layout_entity->getLayoutCanvasInstance();  // LayoutCanvas object

// Iterate elements
foreach ($canvas->iterateCanvas() as $element) {
  if ($element->isComponent()) {
    $component_id = $element->getComponentID();
    $model = $element->getModel();
    $values = $model->getValues();
    // $values is a stdClass with UUID-keyed properties
  }
}
```

### Revision table bloat

Every node save creates a `cohesion_layout` revision. On high-edit nodes (homepages, landing pages), the `cohesion_layout_revision` table can become enormous. Check its size before extraction:

```sql
SELECT
  TABLE_NAME,
  ROUND(DATA_LENGTH / 1024 / 1024, 2) AS data_mb,
  TABLE_ROWS
FROM information_schema.TABLES
WHERE TABLE_NAME LIKE 'cohesion_layout%';
```

## Custom Styles vs. API Styles

Two styling mechanisms. They overlap but work differently.

### Custom styles

Created through Site Studio > Styles > Custom styles. Each produces a CSS class name. Applied to elements through a dropdown in the style tab. Stored as `cohesion_custom_style` config entities.

Class naming pattern: `.coh-style-{machine-name}` (e.g., `.coh-style-padding-bottom---large`).

Custom styles can extend a parent style. The child inherits all parent properties and overrides specific values.

### API styles (Style tab)

Per-element inline styles configured through the Style tab on each element in the layout canvas. These get compiled into generated CSS by the Site Studio API. The CSS is stored in `sites/default/files/cohesion/styles/`.

API styles support the full range of CSS properties: font, background, layout, borders, transforms, transitions, content, filters. Each property can be set per breakpoint.

### What to extract

For custom styles: export the config YAML. Parse the `json_values` to extract the CSS properties per breakpoint.

For API styles: these live inside the model entries of each element in the layout canvas JSON. Extract them as part of the canvas parsing.

## Asset Library

Site Studio allows custom CSS and JS files uploaded through the admin UI. These get stored as Drupal file entities and referenced by Site Studio config.

### Locating uploaded assets

```sql
-- Find files referenced by cohesion entities
SELECT fm.uri, fm.filename, fm.filemime
FROM file_managed fm
JOIN file_usage fu ON fu.fid = fm.fid
WHERE fu.module = 'cohesion';
```

### CSS/JS in components

Components can reference CSS and JS libraries. Custom components (code-defined, not UI-defined) have a file structure:

```
/modules/custom/my_module/components/my_component/
  my_component.json          # Component definition
  my_component.twig          # Twig template (or .html)
  my_component.css           # Styles
  my_component.js            # JavaScript
```

### Icon font libraries

Stored in website settings. Icon fonts are uploaded as zip files containing SVG/font files and a JSON manifest (Fontello or Icomoon format). Files land in `public://cohesion/icon_libraries/`.

## Export Approaches

### Approach 1: Site Studio package export (recommended)

Uses the `cohesion_sync` sub-module. Produces YAML package files with file dependencies and validation metadata.

```bash
# Enable sync module
drush en cohesion_sync -y

# Full package export to default sync directory
drush sitestudio:package:export

# Export to a custom path
drush sitestudio:package:export --path=/tmp/sitestudio-export

# List available packages
drush sitestudio:package:list
```

The export directory structure:

```
sitestudio-export/
  cohesion_component.cpt_hero_banner.yml
  cohesion_component.cpt_card.yml
  cohesion_custom_style.max_width_narrow.yml
  cohesion_content_templates.node_article_full.yml
  cohesion_master_templates.default.yml
  cohesion_website_settings.cohesion_color.blue.yml
  ...
```

Each YAML file contains the full config entity including `json_values`.

### Approach 2: Drupal config export with manual handling

```bash
# Standard config export
drush config:export --destination=/tmp/config-export

# Filter Site Studio configs
ls /tmp/config-export/cohesion_* | wc -l
```

This misses file entity dependencies and does not trigger rebuilds. Use only when the sync module is unavailable.

### Approach 3: Direct database extraction

For the content layer (per-entity layouts), database extraction is required regardless of approach. The package export only covers config entities (templates, components, styles). Node-level layout canvas data lives in the `cohesion_layout` table.

```bash
# Export all cohesion_layout entities as JSON
drush eval '
  $storage = \Drupal::entityTypeManager()->getStorage("cohesion_layout");
  $ids = $storage->getQuery()->accessCheck(FALSE)->execute();
  foreach ($storage->loadMultiple($ids) as $entity) {
    $data = [
      "id" => $entity->id(),
      "parent_type" => $entity->get("parent_type")->value,
      "parent_id" => $entity->get("parent_id")->value,
      "parent_field_name" => $entity->get("parent_field_name")->value,
      "json_values" => json_decode($entity->getJsonValue()),
    ];
    echo json_encode($data) . "\n";
  }
' > cohesion_layouts.jsonl
```

### Approach 4: JSON:API (if sitestudio_jsonapi is enabled)

The `sitestudio_jsonapi` module exposes layout canvas data through Drupal's JSON:API. Limited to component form field values on nodes — no styles or template data.

```bash
# Fetch nodes with their layout canvas data
curl -s "https://example.com/jsonapi/cohesion_layout/cohesion_layout" \
  -H "Accept: application/vnd.api+json" | python3 -m json.tool
```

The JSON:API output strips style and template data. It returns only the structured content values from component form fields — useful for headless migration targets.

## Rebuild and API Dependency

Site Studio templates and styles are compiled by an external API hosted by Acquia. The API key is stored in `cohesion.settings`:

```bash
drush config:get cohesion.settings api_key
drush config:get cohesion.settings organization_key
```

A rebuild regenerates all Twig templates and CSS:

```bash
drush cohesion:rebuild
```

During migration, you do not need the API. The raw JSON in `json_values` contains all the structural and content information. The API-generated assets (Twig, CSS) are rendering artifacts. Your target platform will handle rendering differently.

**What you need from the JSON:**
- Component tree structure (what goes where)
- Content values (text, images, links, entity references)
- Style properties and responsive breakpoints
- Template-to-field mappings (token references)

**What you can ignore:**
- Generated Twig files in `sites/default/files/cohesion/templates/`
- Generated CSS files in `sites/default/files/cohesion/styles/`
- The `previewModel` in the canvas JSON
- The `mapper` in the canvas JSON (internal mapping for the visual editor)

```bash
# Preferred: use Site Studio sync

# Fallback: copy from config sync directory
mkdir -p ./sitestudio-export

```

### Step 3: Export content-level layouts

```bash
drush eval '
  $storage = \Drupal::entityTypeManager()->getStorage("cohesion_layout");
  $ids = $storage->getQuery()->accessCheck(FALSE)->execute();
  $out = fopen("php://stdout", "w");
  foreach ($storage->loadMultiple($ids) as $entity) {
    fwrite($out, json_encode([
      "id" => (int) $entity->id(),
      "parent_type" => $entity->get("parent_type")->value,
      "parent_id" => (int) $entity->get("parent_id")->value,
      "parent_field_name" => $entity->get("parent_field_name")->value,
      "json_values" => json_decode($entity->getJsonValue()),
    ]) . "\n");
  }
  fclose($out);
' > content-layouts.jsonl
```

### Step 4: Export file dependencies

```bash
# Get all files used by cohesion
drush eval '
  $query = \Drupal::database()->select("file_usage", "fu");
  $query->join("file_managed", "fm", "fm.fid = fu.fid");
  $query->fields("fm", ["fid", "uri", "filename", "filemime"]);
  $query->condition("fu.module", "cohesion");
  foreach ($query->execute() as $row) {
    echo json_encode($row) . "\n";
  }
' > cohesion-files.jsonl
```

### Step 5: Export website settings (colors, fonts, grid)

```bash
# Colors
drush config:get cohesion_website_settings.cohesion_color --format=json > colors.json

# Font stacks
for f in config/sync/cohesion_website_settings.cohesion_font_stack.*; do
  cat "$f"
  echo "---"
done > font-stacks.yml

# Responsive grid
drush config:get cohesion.settings responsive_grid_settings --format=json > grid.json
```

### Step 6: Export style guides

```bash
for sg in config/sync/cohesion_style_guide.*; do
  cat "$sg"
  echo "---"
done > style-guides.yml
```

## Parsing the Canvas for Migration

### Flatten the component tree

Walk the `canvas` array recursively. For each element, look up its model data by UUID. For component elements, resolve the `componentId` to the component config entity to understand the form field schema.

```python
import json

def walk_canvas(canvas, model, depth=0):
    """Recursively walk the canvas tree, yielding element data."""
    for element in canvas:
        uuid = element.get("uuid", "")
        elem_type = element.get("type", "")
        elem_data = model.get(uuid, {})

        yield {
            "depth": depth,
            "type": elem_type,
            "uid": element.get("uid", ""),
            "title": element.get("title", ""),
            "component_id": element.get("componentId"),
            "uuid": uuid,
            "model_data": elem_data,
            "enabled": element.get("enabled", True),
        }

        # Recurse into children
        children = element.get("children", [])
        if children:
            yield from walk_canvas(children, model, depth + 1)

# Usage
with open("content-layouts.jsonl") as f:
    for line in f:
        record = json.loads(line)
        jv = record["json_values"]
        canvas = jv.get("canvas", [])
        model = jv.get("model", {})
        for item in walk_canvas(canvas, model):
            print(f"{'  ' * item['depth']}{item['type']}: {item['title']}")
```

### Map component fields to content

For each component instance, the model entry contains field UUIDs as keys. To understand what each UUID means, load the component definition and inspect its form builder:

```python
import yaml

def load_component_fields(component_file):
    """Extract form field definitions from a component config YAML."""
    with open(component_file) as f:
        config = yaml.safe_load(f)

    json_values = json.loads(config.get("json_values", "{}"))
    canvas = json_values.get("canvas", [])
    model = json_values.get("model", {})

    fields = {}
    for element in walk_canvas(canvas, model):
        if element["type"] in ("form-input", "form-wysiwyg", "form-select",
                                "form-toggle", "form-image", "form-link",
                                "form-color-picker", "form-entity-reference"):
            fields[element["uuid"]] = {
                "type": element["type"],
                "title": element["title"],
                "machine_name": element["model_data"].get("settings", {}).get("machineName"),
            }
    return fields
```

## Key Gotchas

1. **json_values is double-encoded.** In config YAML, `json_values` is a string containing JSON. In the database, the `json_values` column is also a string. Always `json_decode` / `json.loads` before processing.

2. **UUIDs are not stable across environments.** Component instances on nodes reference component definitions by `componentId` (the config entity machine name), but model entries use UUIDs generated at creation time. The same component placed twice on a page gets different UUIDs.

3. **The model can reference style guide tokens.** If a field uses a token instead of a static value, the `variableFields` map flags it. The actual token string appears in the field value as `[style-guide:machine-name]`.

4. **Custom styles generate class names.** When a model value is a string like `coh-style-padding-bottom---large`, it references a `cohesion_custom_style` config entity. Resolve the class back to its CSS properties through the style's `json_values`.

5. **Cohesion layout revisions pile up.** The `cohesion_layout_revision` table can hold millions of rows on busy sites. Use `drush err:purge cohesion_layout` (from entity_reference_revisions module) to clean up before extraction, or scope your SQL queries to current revisions only.

6. **File references in the JSON.** Image uploaders and background images store file paths as `public://` URIs. Map these to actual files on disk at `sites/default/files/`.

7. **The API key is not needed for extraction.** You need the key only if you want to trigger a rebuild. For read-only export, the API connection is irrelevant.

8. **Site Studio packages are not Drupal config.** Do not mix `drush config:export` with `drush sitestudio:package:export`. They produce different outputs. Use the package system for Site Studio entities and Drupal config export for everything else. Configure Config Ignore and Config Split to keep them separated.

## Acquia Cloud and Site Factory Integration

Sites running on Acquia Cloud store the API key in environment variables:

```php
// settings.php
$config['cohesion.settings']['api_key'] = getenv('SITE_STUDIO_API_KEY');
$config['cohesion.settings']['organization_key'] = getenv('SITE_STUDIO_AGENCY_KEY');
```

On Acquia Site Factory (ACSF), multiple sites share a single codebase but each has its own database and style guide overrides. When migrating from ACSF + Site Studio:

1. Extract the shared component/template config once from the codebase
2. Extract per-site layout canvas data from each site's database
3. Extract per-site style guide values from each site's theme settings
4. Cross-reference skill 36 for ACSF multi-site extraction patterns
